## What changed

Routact is the first release under this name. It starts from runner-fallback-action 1.0.2 and keeps its `primary-runner` and `fallback-runner` inputs.

- A `config` input (usually the `ROUTACT_CONFIG` organization variable) routes several named pools in one step. Each pool has an ordered `fallback` chain. A step can depend on built-in checks (`idle`, `var`, `env`, `github-minutes`, `command`, `not`, `any`).
- The fallback must run the same OS and architecture as the primary (`platform-check`).
- Busy runners do not count as available, runner lists are read past the first page, and labels match without case.
- A pull request from a fork always gets the fallback.
- An opt-in `claim` lock reserves a specific idle runner, so concurrent runs do not pick the same one.
- The reusable workflow `.github/workflows/route.yml` runs the route job with a GitHub App token.
- The action runs on Node 24.

Pin `SolZeroAI/routact@v2`, or `SolZeroAI/routact/.github/workflows/route.yml@v2` for the reusable workflow.
